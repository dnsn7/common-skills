# 数模论文-skill

将题目、数据、代码和图表串成可核查的竞赛论文。先回答每问，再说明模型如何产生答案；表达清楚、突出建模目的与效果。此 Skill 不把任何旧论文的数字、结论或赛制当作新题事实。

## 启动与输入

1. 先读当前项目规则、题目原文、数据说明、代码、配置、日志/结果表、图表及图源数据，再读用户指定的参考论文/模板。修改既有文件前理解章节、样式、引用和版本关系。不要因文件名相似就混用新旧模型或结果。
2. 开工前一次性列出影响全局的缺口：当届官方格式与匿名要求、目标交付物（聊天/DOCX/PDF/MD）、论文覆盖哪些问、参考款式的具体文件、缺失的运行结果与可否重跑。能从现有材料确认的不要再问。若仍缺材料，先完成可独立完成的证据盘点与结构设计；不得以假设填结果。
3. 建立逐问证据表：`题目要求｜输入及来源｜代码/模型｜参数和求解｜结果表/图｜检验｜结论边界｜正文位置`。逐一核对代码定义、图的横纵轴/颜色/单位、表格口径及输出时间；留意训练、验证、模拟、插值、外推是否混杂。
4. 优先级：当届官方要求、用户明确要求、项目规则、已确认参考款式、通用建议。若未要求保存文件，直接在聊天中给信息；请求 MD 时新建带递增数字编号的文件，不覆盖旧稿。论文文件优先可编辑 DOCX，PDF 依交付要求另出。

## 论文构造

1. 先设计总架构与逐问接口：题意要求 → 数据处理 → 模型建立与求解 → 结果与检验 → 本问结论 → 下一问使用什么输出。标题写出对象、动作与目的；避免只有算法名称或空泛的“分析”。摘要逐问写目的、方法、真实结果和意义，与正文数字、单位一致。
2. 每问先用自然语言写 `输入 → 处理 → 输出 → 下一去向`，接着交代为何选择该模型、变量/维度/单位、目标函数或损失、约束、求解步骤和参数依据。公式前说明目的，公式后定义符号并解释其在代码中怎样求出。新术语和英文缩写首次出现要释义；文字尽量让高中生也能跟上，但不牺牲准确性。
3. 结果段先直接答题，再给核心指标、同口径基线、改善或误差、条件解释、适用范围和下一问用途。将“观察值/真实测量”“拟合结果”“校准或半合成结果”“模型预测/外推”“情景假设”明确分层。保存的历史输出不得称作本次重跑；启发式或有限网格结果不得无证据称为全局最优。
4. 每张图表都要承担方法说明、直接答案、比较或检验。正文先引图表，再就近放置；解释它为什么画、轴/颜色/子图/样本代表什么、读出什么、回答题目哪一项、有哪些边界。图中文字、指标、取样范围须与代码和结果表核对；不能靠图形外观臆测含义。精确值优先表，趋势与关系优先图；不要为了凑数量重复放图。
5. 每问末尾用短段收束答案及下一问接口。全篇结尾归纳模型作用、可验证效果、失败情形与局限。不得把算法清单、背景综述或排版装饰放在模型与结果之前。

## 款式与可编辑性

- 先核对当届官方模板；参考旧稿只继承用户认可的结构和视觉习惯，不继承错误或旧题数值。既有论文反复整改形成的检查点见 [references/revision-checks.md](references/revision-checks.md)，只将其中可迁移的规则用于新题。
- 对有 Word 要求的论文，公式独立成行、右侧自动编号，文内使用可更新的交叉引用；文字、表格、公式保持可编辑。图表自动题注，图题在下、表题在上，表格优先统一三线表。不要将公式截图当作可编辑公式，也不要手工写死引用号。
- 匿名、页码起始页、字体、字号、行距、页眉/页脚均服从本届规范。某次作品曾指定“黑体标题、正文小四宋体、单倍行距、无页眉和身份标识、摘要页起页码、页脚居中”；这些是该次作品要求，不能自动冒充其他赛事通则。
- 排版前先稳定内容与证据；逐页检查图表清晰度、公式裁切、孤立标题、题注分离、长表分页、异常空白页、页码及匿名信息。不得用极小字号掩盖篇幅问题。优先保留原图清晰度，不把上采样当作恢复细节。

## 反复整改所指向的错误

- “突出模型”要求写清建模目的、输入输出、模型选择理由、目标/约束、求解器、效果与用途；不能只罗列名称或把图排漂亮。
- “流程要自然”要求每段有来由和去向，以短而连贯的中文说明模型链；不要连排公式、堆术语、只贴图不解读。
- “效果/好处”须由同条件比较和真实结果支撑；没有验证就写待验证，不能编造性能提升、数据量、实验或文献。
- 逐项对齐题目原问；未完成的问保留明确空位，不代写结论。旧文中的过期章节、过期公式、结果版本必须先辨认再整合。
- 区分样本级指标与聚合展示，说明指标数量、缺失/剔除、权重来源和方向变换依据；不能随意把指标取 `1−x` 或将不同来源数据行拼接。
- AI 使用说明如被要求，应与真实工作流程相符；工具名、版本、日期无记录时不编。AI 建议、代码与措辞本身不是结论证据。

## 交付验收

1. 对照证据表检查每问、每个实质数值、每张图表、每条引用是否能回到题目/代码/结果源。核对数据划分、单位、统计口径、改善率分母、模型边界和参考文献。必要时运行相关代码或检查现有日志；若未运行，明确写“未重跑”。
2. 检查公式、图表和文献的自动编号/交叉引用；生成 DOCX/PDF 后实际打开或渲染全部页面，修复可见问题。纯文字/结构改动也要做相关静态评估。
3. 汇报先说结果，再说改了什么、验证了什么、尚有哪些未核实项。不要用旧稿通过的检查代替新稿检查。
